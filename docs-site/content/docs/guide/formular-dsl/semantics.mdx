Parsing produces a typed AST; **validation** enforces pharmacometric constraints
before any code is generated. The validator (`validate_dsl`) is lane-aware and
accumulates all violations (non-fail-fast) rather than stopping at the first.

## Semantic validation rules

| Rule | Constraint |
| --- | --- |
| Positivity | Volumes, rates, clearances, sigmas must be &gt; 0 |
| Unit interval | `MixedFirstZero.frac ∈ (0, 1)` exclusive |
| Non-negative | `tlag ≥ 0` |
| Positive integer | Transit `n`, NODE `dim` must be ≥ 1 |
| NODE lane admissibility | NODE modules rejected in the Submission lane |
| NODE dim ceilings | `dim ≤ min(template_max_dim, lane_ceiling)` |
| Block IIV | `structure=block` requires ≥ 2 params |
| TMDD requires Linear elim | `TMDD_Core` / `TMDD_QSS` require `Linear` elimination |
| No duplicate IIV params | A parameter cannot appear in multiple IIV blocks |
| No duplicate covariate links | A `(param, covariate)` pair cannot appear twice |
| No variability on Transit `n` | Transit `n` cannot carry IIV/IOV/CovariateLink |
| Params exist | IIV/IOV/CovariateLink must reference a structural parameter |
| `initial:` missing (`FRM-AST-012`) | A used calibration parameter has no value |
| `initial:` unused (`FRM-AST-013`) | An `initial:` value no module references |
| Prior target/family match | `(target_kind, family)` must be admissible |
| Informative-prior justification | `historical_data` / `expert_elicitation` / `meta_analysis` require justification |

<Callout type="info">
  Two block-cardinality checks (missing/duplicate, `FRM-AST-010` / `FRM-AST-011`) run
  earlier, on the raw parse tree, and raise `FormularCompileError` rather than appearing
  in the validator's returned list. See the [error codes](/docs/guide/formular-dsl/error-codes).
</Callout>

### Example rejections

```text
MixedFirstZero(ka, dur, frac) with initial: { frac = 1.5 }
  → ValidationError: MixedFirstZero.frac must be in (0, 1), got 1.5

IIV(params=[CL], structure=block)
  → ValidationError: block IIV requires >= 2 params, got 1

NODE_Absorption(dim=6, constraint_template=monotone_increasing) in Discovery
  → ValidationError: NODE dim 6 exceeds template max 4 for monotone_increasing

absorption: FirstOrder(ka) with no "ka" entry in initial:
  → ValidationError [FRM-AST-012]: 'ka' is used by a structural module but has no
                     value in the initial: block
```

## NODE constraint templates

NODE absorption and elimination modules require a `constraint_template` that restricts
the learned function's shape.

| Template | Meaning | Template max dim |
| --- | --- | --- |
| `monotone_increasing` | Output increases with input | 4 |
| `monotone_decreasing` | Output decreases with input | 4 |
| `bounded_positive` | Output strictly positive | 6 |
| `saturable` | Increases then plateaus (Michaelis–Menten-like) | 4 |
| `unconstrained_smooth` | Smooth only; no shape constraint | 8 |

The effective ceiling is `min(template_max, lane_ceiling)`:

| Lane | Lane ceiling | NODE admissible? |
| --- | --- | --- |
| Submission | — | **No** (hard rule) |
| Discovery | 8 | Yes |
| Optimization | 4 | Yes |

## Backend lowering — one spec, three targets

The same spec lowers to every backend. Consider:

```text
model {
    absorption: FirstOrder(ka)
    distribution: OneCmt(V)
    elimination: Linear(CL)
    variability: IIV(params=[CL, V], structure=diagonal)
    observation: Proportional(sigma_prop=0.1)
    initial: { ka = 1.0, V = 30.0, CL = 2.0 }
}
```

<Tab value="nlmixr2 (R)">

```r
function() {
  ini({
    tka <- log(1.0); tcl <- log(2.0); tv <- log(30.0)
    eta.cl ~ 0.1; eta.v ~ 0.1
    add.sd <- 0.1
  })
  model({
    ka <- exp(tka)
    cl <- exp(tcl + eta.cl)
    v  <- exp(tv + eta.v)
    d/dt(depot)  = -ka * depot
    d/dt(center) =  ka * depot - (cl / v) * center
    cp <- center / v
    cp ~ prop(add.sd)
  })
}
```
